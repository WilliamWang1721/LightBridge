# PR #21 Repair Report

## Product decision preserved

LightBridge groups remain provider-neutral. Protocol conversion between downstream ingress and upstream accounts is intentional. This repair does not introduce an upstream-brand quota or change quota attribution.

## Database and version safety

- Migration 162 is now additive during the rollback-compatibility window. Legacy group columns remain present so an older binary can restart after rollback.
- Version updates require a completed PostgreSQL snapshot on the server side; clients cannot bypass it by omitting `backup_current`.
- Malformed update and rollback JSON is rejected instead of silently disabling backup.
- A failed update restores the pre-update database snapshot before returning an error.
- Full rollback creates a safety snapshot, restores the database snapshot taken before the previous upgrade, rolls back the binary, and restores the safety snapshot if binary rollback fails.
- Uploaded backup objects are deleted and the operation fails if the backup record cannot be persisted.
- Container and unsupported deployments are blocked from backend restart, not only hidden by the frontend.

## Deployment safety

All maintained Docker Compose variants explicitly set `LIGHTBRIDGE_DEPLOYMENT_TYPE=container`, preventing container processes from being mistaken for host-managed binaries.

## CI contract repairs

- OAuth callback tests now provide the required six-digit verification code.
- Payment result tests follow the explicit unverifiable-state contract.
- Provider-neutral gateway tests no longer expect legacy group-platform 404 responses.
- Deprecated in-memory compatibility fields remain accepted for rollback-era clients and tests, but are ignored by routing.

## Security dependency repairs

The final package pins versions generated by GitHub Actions for:

- `google.golang.org/grpc` at or above the govulncheck fixed version `v1.82.1`.
- `golang.org/x/text` at or above the govulncheck fixed version `v0.39.0`.
- A non-vulnerable PostCSS release selected by pnpm, with the generated lockfile included.

## Verification notes

The sandbox cannot run the repository's Go 1.26.5 toolchain or download npm packages directly. Dependency lockfiles were therefore generated on GitHub-hosted runners. Formatting and `git diff --check` were run locally. Remote CI must be rerun against the repaired source before merge or release.

## GitHub runtime and environment verification

A permanent `Runtime & Environment Check` workflow now complements CI and Security Scan.
It validates the pinned Go, Node, pnpm, PostgreSQL, Redis, gRPC, x/text, and PostCSS
contracts; renders every maintained Compose variant; builds all maintained source
artifacts; builds the production Docker image from the checked-out commit; and starts
the complete LightBridge/PostgreSQL/Redis stack.

The full-stack smoke test verifies `/health`, setup completion, the embedded frontend,
public settings, automatic administrator creation and login, the protected version API,
container deployment identity, non-root execution, PostgreSQL client tools, Redis
connectivity, database persistence, application restart, and PostgreSQL/Redis restart
recovery. Runtime diagnostics are uploaded on every run without storing login tokens or
resolved secrets.
